# AI 使用说明（5.2）

工具：阶段一 Cursor Agent；阶段二 Trae Agent（Kimi）。详细 Prompt 见 `AI使用日志.md`。

## 阶段二

**AI 帮了什么**

- 把需求变更 8 条逐条对照现有代码，找出 4 处真实缺口（恢复旧版本、族级使用查询、题库管理与最新版去重、族级跨卷统计）
- 发现阶段一隐患：版本号「查最新+1」并发撞号，无唯一索引兜底
- 给出兼容性方案：新字段 `restored_from` 旧文档按 null 读、统计口径用 `scope` 参数扩展且默认不变、旧非唯一索引启动时自动替换

**自己设计 / 拍板的**

- 恢复 ≠ 回滚：恢复是以旧版内容生成最新版，历史一律不删不改（延续阶段一「版本不可变」的底线）
- `derived_from` 保持版本链连续、`restored_from` 单独记内容来源，两个字段各管各的
- 阶段二报告单独成篇，专写修改过程，阶段一报告原样保留
- 改完后人工逐条核对了 diff 和测试输出

**AI 做错 / 需要改的**

- 阶段二过程顺利，AI 未出明显错误；主要是人对「恢复语义」「默认口径不变」做了约束

## AI 帮了什么

- 读阶段一和需求变更文档，对照功能清单
- 把我一开始「题库嵌问卷、版本再开一个库」的想法改成四集合 + 一版一文档
- 按我选的技术栈（模板 + Session Cookie）写 FastAPI 骨架、页面、API、pytest
- 跳转/校验从数据里读规则，没有写死某一份问卷
- 后来按作业格式整理文档和测试步骤

## AI 做错了什么 / 需要改的

- 测试里第二次 `client()` 会换一套空库，统计接口报「问卷不存在」；改成同一 client，并切回 owner 再查统计
- 想用 passlib，环境没装；改成标准库 PBKDF2
- 上级 `README.md` 一度写「需求变更先不做」，和实际范围不一致，已改
- 结构文档写的太多太长
- 把schema中加入了写死的设计，当作范例，如categoty类里写了具体的 ："人口统计”

## 自己设计了什么

- 范围：阶段一功能 + 需求变更一起做，不为阶段二推倒重做
- 题库存独立集合，版本不另开库
- 不做 snapshot，问卷只引用某一版 `question_id`
- 改题保存 = 自动新版本并提示，旧版不能直接改内容
- 填写必须注册登录（方便统计和溯源）；匿名只是答卷上的标记
- 分享按用户名写入 `shared_with`，被分享者可引用、不能改原版
- 技术栈不用 Vue / JWT
- 字段的设计
- 结构文档，md文档的二次审查
