# AI 使用说明（5.2）

工具：Cursor Agent（本机）。详细 Prompt 见 `AI使用日志.md`。

## AI 帮了什么

- 读阶段一和需求变更文档，对照功能清单
- 把我一开始「题库嵌问卷、版本再开一个库」的想法改成四集合 + 一版一文档
- 按我选的技术栈（模板 + Session Cookie）写 FastAPI 骨架、页面、API、pytest
- 跳转/校验从数据里读规则，没有写死某一份问卷
- 后来按作业格式整理文档和测试步骤

## AI 做错了什么 / 需要改的

- 测试里第二次 `client()` 会换一套空库，统计接口报「问卷不存在」；改成同一 client，并切回 owner 再查统计
- 想用 passlib，环境没装；改成标准库 PBKDF2
- 上级 `README.md` 一度写「需求变更先不做」，和实际范围不一致，已改
- 结构文档写的太多太长
- 把schema中加入了写死的设计，当作范例，如categoty类里写了具体的 ："人口统计”

## 自己设计了什么

- 范围：阶段一功能 + 需求变更一起做，不为阶段二推倒重做
- 题库存独立集合，版本不另开库
- 不做 snapshot，问卷只引用某一版 `question_id`
- 改题保存 = 自动新版本并提示，旧版不能直接改内容
- 填写必须注册登录（方便统计和溯源）；匿名只是答卷上的标记
- 分享按用户名写入 `shared_with`，被分享者可引用、不能改原版
- 技术栈不用 Vue / JWT
- 字段的设计
- 结构文档，md文档的二次审查

## 自己改了什么

- 否决「题目嵌进问卷」「版本嵌套库」
- 确认校验和跳转都放在文档字段里
- 密码哈希、测试用 mongomock、日志改成原话 Prompt
- 核对提交清单后补了 schema、项目文档、测试用例、完成报告
- md，word等结构文档
- schema的格式和内容
